# 오류 흐름 점검 — 2026-10-27

기존 48개에 오류 시나리오 16개를 추가했습니다. 사용자 데이터 대신 독립된 메모리 SQLite와 임시 파일 폴더를 사용했습니다. 저장 경합은 저장소 응답을 의도적으로 지연시켜 재현했습니다.

## 발견하고 수정한 문제

| 시나리오 | 수정 전 결과 | 수정 |
|---|---|---|
| 저장 중 뒤로 가기 | 저장 요청이 두 번 실행됨 | 저장·종료 단일 처리, 진행 중 재요청 차단 |
| 뒤로 가기 연속 입력 | 저장 요청이 두 번 실행됨 | 같은 종료 상태를 공유하고 화면을 한 번만 닫음 |
| 입력 없이 편집기 종료 | 빈 초안 레코드가 생김 | 내용 없는 초안은 남기지 않음 |
| 첨부파일 내용 충돌 | 미리보기 충돌 0건, 실제 복원 단계에서 실패 | 미리보기에서 기존 파일의 내용 충돌도 계산 |
| 알 수 없는 보드 종류 | 검증을 통과함 | 허용된 보드 종류만 가져옴 |
| favorite=2 등 잘못된 상태 | 검증을 통과함 | 0·1 상태 값과 필드 자료형 검사 |
| 휴지통 속 잘못된 자료 종류 | 검증을 통과함 | 중첩된 삭제 자료에도 같은 검증 적용 |

저장 중에는 입력 변경과 추가 편집을 막습니다. 자료 저장과 해당 초안 제거는 하나의 DB 트랜잭션으로 묶었습니다. 앱이 저장 도중 비활성화되어도 별도 초안 저장을 다시 요청하지 않습니다. 제목 없이 본문·속성만 작성한 경우에는 해당 내용의 초안을 보존합니다.

## 추가 검증

### 편집·화면 이동 4개

- 저장 중 뒤로 가기: 저장 한 번, 부모 인물 목록 유지
- 뒤로 가기 연속 입력: 저장 한 번, 부모 목록 유지
- 작성하지 않은 편집기 종료: 인물·빈 초안 없음
- 저장 중 앱 비활성화: 인물 저장 후 초안이 되살아나지 않음

### 잘못된 백업 8개

- 깨진 ZIP·지원하지 않는 버전 거부, 기존 자료 유지
- 기존 첨부파일의 내용 충돌을 미리보기에 반영
- 알 수 없는 보드 종류 거부
- 잘못된 상태 값 거부
- 휴지통 내부 자료의 잘못된 종류 거부
- 첨부 경로 탈출·뒤늦은 첨부 누락 시 DB·새 파일을 남기지 않음
- 다른 작품을 참조하는 보드 노드 거부
- 숫자 좌표 대신 문자열을 넣은 자료 거부

### 관계도 상태 전환 4개

- 중심 인물·1/2단계·관계 종류 필터 전환
- 중심 인물 제거 후 실행 취소
- 두 보드와 전체 관계도를 3회 반복 전환, 보드별 멤버 분리
- 관계도에서 새 인물 등록 취소, 빈 인물·초안·오류 없음
