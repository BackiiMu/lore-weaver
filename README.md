# 로어 위버

Flutter 기반 오프라인 소설 세계관·인물 관계도 관리 앱입니다. 서버, 로그인, 외부 API 없이 기기 안의 SQLite 데이터베이스와 앱 전용 첨부파일 저장소를 사용합니다. 기본 언어는 한국어입니다.

현재 핵심 관리 기능은 구현되어 있고, iOS 시뮬레이터에서 실행했습니다. **스토어 출시 검증까지 완료된 상태는 아닙니다.** Android 빌드 환경 문제와 아래 제한 사항을 확인해주세요.

## 실행

```sh
flutter pub get
flutter run
```

여러 장치가 연결되어 있으면 `flutter devices`로 ID를 확인하고 `flutter run -d <장치 ID>`로 실행합니다. iOS는 Xcode, Android는 Android SDK와 호환 JDK가 필요합니다. 개발 의존성 설치와 빌드에는 인터넷이 필요할 수 있지만 앱의 핵심 기능에는 필요하지 않습니다.

```sh
flutter analyze
flutter test
flutter build ios --simulator --no-codesign
flutter build apk --debug
```

## 화면과 사용법

| 화면 | 구현 내용 |
|---|---|
| 작품 서재 | 생성·수정·삭제·복제, 제목 검색, 수정순, 표지 등록, 인물·세력·사건 수 |
| 작품 대시보드 | 실제 데이터 통계, 최근 자료, 즐겨찾기, 빠른 등록, 관계도 이동 |
| 등장인물 목록 | 검색, 이름순·수정순, 즐겨찾기, 태그·소속 세력 필터, 이미지 |
| 자료 상세·편집 | 인물 기본·추가 정보, 자유 속성, 이미지·파일 첨부, 양방향 연결 탐색 |
| 인물 관계도 | 이미지·이름 노드, 드래그, 확대·축소·화면 이동, 인물 중심 필터, 전체 맞춤, 자동 배치, 좌표 저장, PNG |
| 세력·조직 | CRUD, 다중 소속 관계, 대표자·상위 조직 연결, 세력 관계·조직도 |
| 지역·지도 | CRUD, 상위 지역 연결, 이미지 지도, 장소 마커 저장·삭제·상세 이동 |
| 사건 연표 | CRUD, 자유 연호·시간 문자열, 날짜 없는 순서, 중요도, 긴 누르기로 재정렬, 참여자·선행 사건 연결 |
| 설정 자료실 | 제목·본문, 자유 카테고리·태그·속성, 첨부·상호 연결 |
| 통합 검색 | 같은 작품의 모든 자료 제목·본문·속성·태그 검색, 유형 필터, 상세 이동 |
| 자동 저장 초안 | 입력 후 500ms 뒤 저장, 백그라운드 전환 시 저장 시도, 초안 복구·삭제 |
| 설정·백업 | 테마 저장, 전체·작품별 ZIP, 검증 후 복원, 첨부 정리, 전체 초기화, 앱 정보 |

작품을 열고 왼쪽 메뉴에서 자료 유형을 고릅니다. 자료를 저장한 뒤 상세 화면의 연결 추가 버튼으로 다른 자료와 연결합니다. 같은 작품의 자료만 선택할 수 있습니다. 연결은 한 번 저장하면 양쪽 상세 화면에서 조회됩니다.

관계 선택 버튼에는 가족, 부모·자녀, 형제, 스승·제자, 연인, 친구, 동료, 동맹, 적대, 라이벌, 소속·구성원, 대표자, 상위 조직·지역, 참여 사건, 선행 사건이 있습니다. 직접 관계 이름과 역방향 이름도 입력할 수 있습니다. 예를 들어 인물에서 세력으로 `소속`, 역방향으로 `구성원`을 지정하면 소속 필터에서도 사용됩니다.

지도는 지역 상세에서 이미지를 첨부하고 지도 버튼으로 엽니다. 상단 마커 추가 모드에서 장소를 선택한 뒤 이미지 위를 누릅니다. 좌표는 이미지 너비·높이에 대한 0~1 비율로 저장합니다. 마커를 누르면 연결한 장소로 이동하거나 마커를 삭제할 수 있습니다.

관계도의 캔버스 제거는 인물 삭제와 다릅니다. 숨긴 노드는 + 메뉴에서 다시 추가합니다. 인물 삭제는 상세 화면에서 휴지통으로 옮기며 영구 삭제는 휴지통에서 수행합니다. 관계 수정·삭제는 관계선을 선택하거나 인물 상세의 연결 목록에서 수행합니다. PNG 내보내기는 현재 보이는 캔버스 영역을 저장합니다. 전체 맞춤 후 내보내면 전체 그래프를 포함할 수 있습니다.

연표의 순서 변경은 검색·필터와 이름순을 해제한 기본 순서 화면에서 가능합니다. 가상 날짜는 문자열로 보관하고 실제 순서는 숫자로 관리합니다. 날짜 문자열을 자동 해석해 정렬하지 않습니다.

## 패키지

직접 사용하는 패키지는 `flutter_riverpod`, `go_router`, `drift`, `path_provider`, `uuid`, `file_picker`, `archive`, SDK의 `flutter_localizations`입니다. 테스트에는 `flutter_test`, 분석에는 `flutter_lints`를 사용합니다. SQLite 네이티브 라이브러리는 Drift가 사용하는 sqlite3 패키지의 빌드 자산으로 제공됩니다.

Drift의 `GeneratedDatabase`와 사용자 SQL로 스키마·쿼리·트랜잭션·마이그레이션을 관리합니다. 생성 코드나 build_runner 실행은 필요하지 않습니다. 파일 데이터베이스는 백그라운드 실행 영역에서 엽니다. Riverpod은 자료 변경 알림과 테마 상태에 사용하고 화면은 변경 알림에 맞춰 쿼리를 다시 실행합니다.

## 데이터베이스와 삭제 정책

스키마 버전은 **3**이며 v1→v3 및 v2→v3 업그레이드를 테스트했습니다.

| 테이블 | 역할 |
|---|---|
| works | 작품 제목, 장르, 설명, 수정 시점 |
| entities | 작품별 인물·세력·지역·사건·설정, 제목·본문·종류·즐겨찾기·속성 JSON |
| links | 자료 간 연결, 정·역방향 이름, 방향성 |
| layouts | 자료별 그래프 좌표와 캔버스 표시 여부 |
| attachments | 자료에 연결된 앱 전용 파일명 |
| covers | 작품 표지 파일명 |
| markers | 지도와 장소 참조, 이미지 위 정규화 좌표 |
| drafts | 확정 전 작성 내용과 사용자 속성 |
| boards / board_nodes | 목적별 관계 보드와 보드별 인물·배치 |
| catalog | 작품별 태그·설정 카테고리 목록 |
| trash | 삭제한 작품·자료와 종속 레코드 복구 스냅샷 |

요청에 제시된 Characters/Factions/Locations/Events/LoreEntries는 공통 `entities`로, 각종 관계·소속·참여는 `links`로 통합했습니다. 태그·사용자 정의 속성·자료 카테고리 값은 속성 JSON에 저장하며 등록된 태그·카테고리 이름은 catalog에서 관리합니다. 별도의 Tags/EntityTags/CustomFields 테이블은 두지 않았습니다. SQL로 직접 모델을 확장할 때 이 설계 차이를 고려해주세요.

- 모든 연결, 첨부, 좌표, 지도 마커는 `(work,id)` 복합 외래 키로 작품 경계를 보장합니다.
- UI에서 자료를 삭제하면 먼저 종속 레코드를 휴지통에 보관한 뒤 활성 DB의 관련 연결·좌표·첨부·마커를 cascade 삭제합니다. 휴지통 복원 시 참조가 유효하면 함께 복구합니다.
- UI의 작품 삭제도 작품과 모든 종속 레코드를 휴지통에 보관합니다. 직접 SQL로 삭제하면 휴지통 보관 없이 cascade 삭제되므로 사용자 삭제는 TrashService를 사용합니다.
- 물리 첨부파일은 즉시 삭제하지 않습니다. 복제 작품에서 같은 파일을 참조할 수 있으므로 설정의 첨부 정리에서 모든 작품과 휴지통의 참조가 없는 파일만 삭제합니다.
- 작품 복제는 자료·연결·좌표·마커 ID를 다시 만들며 첨부파일은 공유합니다. 미완성 초안은 복제 대상에 포함하지 않습니다.
- 상위 조직·지역 및 선행 사건 연결은 편집 저장 시 유형과 순환 여부를 검사합니다. 가져온 ZIP은 SQL 외래 키 무결성을 검증하며 사용자 정의 관계의 의미까지 검증하지는 않습니다.
- 인물·자료 편집 내용은 초안으로 저장하고 저장 버튼·뒤로 이동 시 확정합니다. 강제 종료 직전 마지막 500ms 이내 입력까지의 보존은 보장할 수 없습니다.

## 백업·복원

현재 ZIP manifest 포맷은 **4**, 이전 포맷 1~3의 가져오기도 지원합니다. 보드·태그 목록·휴지통 자료도 포함합니다. ZIP에는 `manifest.json`과 `media/` 아래 이미지·첨부파일·표지를 포함합니다. 확정 전 자동 저장 초안도 전체·작품별 백업에 포함됩니다. 테마 선택은 기기 설정이며 백업 대상에 포함하지 않습니다.

복원은 다음 순서로 처리합니다.

1. 파일 크기·ZIP·포맷 버전·레코드 필드 검증
2. 별도 메모리 SQLite에 전체 데이터를 넣어 ID·외래 키 무결성 확인
3. 첨부 경로·파일 존재·기존 파일 내용 충돌 검사
4. 실 DB에 전체를 하나의 트랜잭션으로 삽입
5. 실패하면 DB 삽입을 롤백하고 새로 복사한 첨부파일 제거

**동일 ID가 존재하는 작품에 덮어쓰거나 자동 병합하지 않습니다.** 충돌하면 복원 전체를 취소합니다. 기존 자료를 별도 백업해 보관한 뒤 해당 작품을 삭제하거나, 비어 있는 설치에서 복원해주세요. ZIP 입력은 200MB, 선언된 압축 해제 총량은 500MB, manifest는 30MB, 테이블당 레코드는 10만 개로 제한합니다. 파일 전체를 메모리에서 처리하므로 큰 백업의 실제 처리 가능 크기는 장치 메모리에도 영향을 받습니다.

- iOS 서명 배포 빌드, Android 실제 실행, 실제 기기 성능·파일 선택·공유 UI의 종단 검증은 수행하지 않았습니다.

## 제한 및 출시 전 남은 작업

- 자동 배치는 격자·계층·연결 구성요소별 묶음을 지원합니다. 물리 기반 힘 배치·교차선 최소화, 수동 드래그 중 자동 충돌 회피는 없습니다. 같은 두 노드의 여러 관계는 곡선으로 분리하지만 모든 복잡한 그래프에서 선 겹침을 제거하지는 않습니다.
- 확대·이동 변환 자체는 재실행 후 복원하지 않고 노드 좌표·숨김 상태를 복원합니다. 위치 변경은 드래그 종료 시 저장됩니다. 회전 중 완료되지 않은 제스처까지 보존하지는 않습니다.
- 지도는 지역에 첨부한 첫 번째 지원 이미지에 마커를 표시합니다. 여러 지도 이미지의 선택·교체 시 마커 재배치는 별도 편집 기능이 없습니다.
- 태그·카테고리는 목록 등록·선택·이름 변경·병합·표시 제거를 지원합니다. 입력 중 자동완성과 유의어 추론은 없습니다.
- 조직·지역 계층은 이름 있는 자료 연결과 접기·펼치기 트리를 지원합니다. 드래그로 트리의 부모를 변경하는 기능은 없으며 연결 편집으로 변경합니다.
- 일반 검색은 작품 자료를 불러와 필터링합니다. 전문검색 인덱스, 페이지 단위 데이터 읽기, 실제 대규모 장치 FPS 계측은 없습니다. 500명 테스트는 기능 검증이며 실기기 성능 보증은 아닙니다.
- 첨부파일은 UUID 기반 파일명으로 보관·내보냅니다. 원본 파일명 관리와 본문 서식 편집은 없습니다.
- 백업 충돌 자동 병합·작품별 덮어쓰기, 암호화 백업, 실파일 쓰기와 DB를 아우르는 프로세스 강제 종료 원자성은 없습니다. 복원 도중 종료된 경우 참조 없는 파일은 정리 메뉴로 제거할 수 있습니다.
- 앱 식별자는 생성 기본값(`com.example.loreWeaver` 등)입니다. 출시용 조직 식별자, 서명, 아이콘·스토어 메타데이터, 개인정보 처리 문서, Android 빌드 환경과 실기기 QA가 남아 있습니다.

초기 데이터는 자동으로 생성하지 않습니다. 테스트의 자료는 별도 임시 DB와 폴더에서 만들고 삭제하므로 실제 앱 데이터에 섞이지 않습니다.
